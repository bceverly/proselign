Documentation

Proselign is at milestone M0: the command-line contract, voice storage and fidelity checks are in place; style transfer quality depends on the local model you connect. Expect changes before 1.0.

Install

Ubuntu (PPA)

Ubuntu 22.04, 24.04 and 26.04 LTS. Packages are built for the architectures the local model tooling supports:

ArchitectureTierLocal inference
amd64, arm64Fullllama.cpp (CPU or GPU), Ollama, vLLM
ppc64el, s390xCPU-onlyllama.cpp or the vLLM CPU backend. No Ollama and no GPU acceleration. Expect a quantized 7–9B model to be usable but slow on many-core POWER and Z systems.
 
sudo add-apt-repository ppa:bceverly/proselign
sudo apt update
sudo apt install proselign

Debian package

Download the .deb for your architecture from the releases page, check it against SHA256SUMS, then:

sudo apt install ./proselign_*_amd64.deb

pip

Any system with Python 3.10 or newer. Proselign has no third-party runtime dependencies.

pip install proselign-*-py3-none-any.whl

From source

git clone https://github.com/bceverly/proselign
cd proselign
sudo make install          # into /usr/local; PREFIX=~/.local for a user install

Run a local model

Proselign rewrites through any server that speaks the OpenAI-compatible chat API. By default it expects one at http://127.0.0.1:8080/v1.

llama.cpp

llama-server -m Qwen2.5-7B-Instruct-Q4_K_M.gguf --host 127.0.0.1 --port 8080

Ollama

ollama pull qwen2.5:7b-instruct
export PROSELIGN_ENDPOINT=http://127.0.0.1:11434/v1
export PROSELIGN_MODEL=qwen2.5:7b-instruct

Proselign sends four chunks at a time (--parallel). Ollama runs them side by side only when it is started with OLLAMA_NUM_PARALLEL set. On a systemd install, add it in a drop-in file and restart Ollama:

sudo mkdir -p /etc/systemd/system/ollama.service.d
printf '[Service]\nEnvironment="OLLAMA_NUM_PARALLEL=4"\n' | sudo tee /etc/systemd/system/ollama.service.d/parallel.conf
sudo systemctl daemon-reload
sudo systemctl restart ollama

IBM POWER and Z (CPU-only tier)

Build llama.cpp from source (it includes POWER and Z vector optimizations) and run llama-server as above, or use vLLM's CPU backend. On s390x, which is big-endian, use a big-endian GGUF model: convert one with llama.cpp's gguf-py tools or download a published big-endian build.

A 4-bit 7–9B model runs well on a 12–16 GB GPU; larger models are worth evaluating on 24–32 GB cards. Bigger is not automatically better for style fidelity, so test with your own writing. Model weights carry their own licenses, separate from Proselign's.

Quick start

# 1. Learn a voice from your own documents (.txt, .md, .docx, .doc, .pdf, .mbox)
proselign train --voice Bryan ~/Documents/Writing/
#    ... and from your blog (every post, read once and kept locally)
proselign train --voice Bryan --append https://example.com/

# 2. Rewrite: stdout carries the result and nothing else
cat draft.md | proselign --voice Bryan > final.md

# 3. Be conservative with a sensitive document
proselign --voice Bryan --strict --strength 0.3 < contract-summary.md

Try the pipeline without a model: --backend mock echoes text through every stage (segmentation, protection, validation), which is useful in scripts and CI.

Command reference

CommandWhat it does
proselign --voice NAME [FILE...]Rewrite stdin (or files; - is stdin) in a voice. Same as proselign rewrite.
proselign train --voice NAME PATH...Learn a voice from .txt, .md, .docx, .doc (Word 6 through 2003) and .pdf files, and .mbox mailboxes of mail you sent (each message is a document; quoted replies, forwards, signatures and attachments are left out); unreadable files are skipped with a warning. --append re-learns with additional documents. --min-words N leaves out documents and messages shorter than N words, to learn from considered writing rather than quick notes.
proselign train --voice NAME URL...Learn from writing published on the web. A blog's front page reads every post (through the WordPress REST API, or else the RSS or Atom feed the site advertises, which may hold only recent posts); a feed URL reads each entry; any other page is read as one article. Navigation, comments, block quotes, tables and code are left out, and so are lines that read as shell commands or settings. Fetched posts are kept as text in the voice's directory, so --append works offline afterwards. --offline refuses non-local URLs. URLs and paths can be mixed.
proselign tune --voice NAMEFine-tune a model on the voice (see Fine-tuning). Rewrites and eval in that voice then use the tuned model; --no-tuned compares without it.
proselign eval --voice NAMERound-trip sample passages through neutral prose and back, and report how much of the gap to the author's own writing the rewrite closed. Accepts the rewrite options, so models (--model) and settings (--examples, --candidates) can be compared. Settings that depart from the author's habits on purpose (passive_voice = off, a forced first_person) are set aside for the measurement. The neutral versions are kept with the voice (never exported) and reused, so every model starts from the same texts; --fresh writes new ones. Because any rewrite changes wording, the same texts are also rewritten with no voice as a control, and the report shows how much closer the voice came than the control (--no-control skips it). --repeats N averages N runs and shows their range, to tell a real difference from noise; a second table shows what each feature contributes to the distance. --ablate rewrites again without each part of the voice in turn (sentence length, contractions, person, passive voice, word length, punctuation, vocabulary, tone, the example passages, the steering feedback) and reports which parts help and which hurt.
proselign voicesList voices: id, name, document count (tab-separated).
proselign inspect NAMEPrint a voice's profile as JSON.
proselign export NAME [-o FILE]Write a portable .proselign archive. Corpus paths are omitted unless --include-sources.
proselign import FILE [--force]Install a voice from an archive. Nothing in an archive is ever executed.
proselign delete NAMEPermanently remove a voice.

Exit status

CodeMeaning
0Success.
1Unexpected error.
2Usage error: bad arguments or unreadable input.
3Voice error: unknown, invalid or conflicting voice.
4Validation error: a rewrite failed fidelity checks under --strict.
5Backend error: the endpoint is unreachable or replied badly.
6Fetch error: a web page given to train cannot be fetched or read.

Markdown documents

proselign --voice Bryan notes.md -o notes-rewritten.md rewrites the prose of a Markdown file and writes Markdown back. Headings, front matter, fenced and indented code, tables and HTML blocks are copied unchanged; emphasis, links and list structure are kept around the rewritten words. When you train on .md files, the markup itself (#, **, link targets, list markers, code) is removed so that only your prose is measured.

Word documents

proselign --voice Bryan report.docx -o report-rewritten.docx rewrites the prose of a Word document and leaves everything else as it was: styles, numbering, headers and footers, tables, images, comments and section settings are copied byte for byte. Only the body text and footnotes are edited, one paragraph at a time, and bold, italic and other formatting inside a paragraph travels with the words it marks.

A title or cover page is left completely alone: a cover page inserted from Word's gallery, or a short first page (under 250 words) that ends in a page or section break (keep_title_page = off in ~/.proselignrc rewrites it too). Elsewhere, a paragraph is left alone when it is a heading, title, caption or table of contents entry; when it is not a full sentence (subject lines, labels, most table cells); when it sits in a table cell with no full stop anywhere in it (labels, figures and column headings, even a line ending in ? or !); or when it holds fields, links, images, tabs, line breaks, hidden text or tracked changes. A summary of what was rewritten and what was kept goes to stderr. The original file is never overwritten.

Fidelity checks

Before a chunk is rewritten, Proselign records its protected tokens: numbers and currency, percentages, document identifiers such as Bates numbers, URLs, e-mail addresses, quotations, citations like [3], list labels and inline code. The model never sees them: each is sent as a placeholder such as {{3}} and put back afterwards. After the rewrite, every token must still be present as many times as before, and so must every name and acronym, every negation and modal verb (not, never, may, will, could), and every sentence: one dropped, or one added that the original has nothing like, fails the check, as does a rewrite far longer or shorter than the original or one that changes who is speaking or addressed. A comma or full stop that the model moves across a closing quote mark is put back first. A rewrite that slips into another writing system (for example Chinese in an English document) has the stray fragment translated back on the fly. Any other failure is retried with the specific problems as feedback; if retries fail, the original text is kept and a warning goes to stderr, or with --strict the run fails with exit status 4.

Then every rewrite is reviewed sentence by sentence. Only sentences that need work are changed: one that breaks a style rule, runs far longer than the author's sentences, or spells out what the author contracts. The model is told which ones and why, and every other sentence is left exactly as written (--every-sentence rewrites all of them). Each changed sentence must pass the checks above on its own and add no name the original does not have; then a second model is asked only whether the two say the same thing: the same people doing the same things, the same tense, certainty and attribution. A sentence that fails gets the author's original back, so one bad sentence no longer costs the good edits around it. Dropped sentences are restored, added ones removed, and list markers, the case of a sentence's first word and the whitespace between sentences always come from the original. The checks are strong but not perfect, so read the changes (diff -u) before sending anything that matters.

Fenced code blocks, indented code, pipe tables, HTML blocks, YAML front matter, e-mail headers and plain-text headings are copied byte for byte and never sent to the model.

Fine-tuning

A prompt can describe a voice, but the model keeps its own habits. proselign tune trains the model itself on the author's writing:

  1. Every passage of the voice's source documents is flattened into neutral prose by the current model, giving pairs of neutral and original text. Facts are masked as placeholders on both sides. The pairs are kept with the voice (never exported) and reused by later runs; --pairs-only stops here and needs no GPU.
  2. A LoRA adapter is trained to turn the neutral text back into the author's (QLoRA: the base model in 4-bit, so a 14B model fits a 16 GB GPU). The 20 passages eval samples are held out of training, so a tuned voice is still measured on writing its model has not seen.
  3. The adapter is converted to GGUF and registered with Ollama, through its API, as proselign-NAME on top of the same base model.

Training needs a CUDA GPU and the optional training libraries, which proselign itself never depends on:

pip install torch==2.9.1 --index-url https://download.pytorch.org/whl/cu128
pip install 'proselign[tune]'
proselign tune --voice Bryan --model qwen2.5:14b-instruct --base Qwen/Qwen2.5-14B-Instruct

--base names the Hugging Face weights behind --model (they are downloaded on first use); --epochs (default 2), --rank (default 16) and --name adjust the training.

Voice format

A voice is a JSON manifest stored in $XDG_DATA_HOME/proselign/voices/<id>/voice.json (by default ~/.local/share/proselign/), readable only by you. It keeps objective measurements (metrics) apart from interpretive hints (style):

{
  "schema_version": 1,
  "voice_id": "bryan",
  "display_name": "Bryan",
  "style": { "tone": ["conversational"], "sentence_length": "short", "paragraphing": "compact" },
  "metrics": { "sentence_length_words": { "mean": 13.4, "median": 12.0, "stdev": 6.1 }, "...": "..." },
  "corpus_summary": { "documents": 214, "words": 186402 },
  "license_and_consent": { "raw_examples_exportable": false }
}

Exported .proselign archives are gzip'd tar files containing only that manifest. Import accepts nothing else: no other members, no links, no oversized files, no executable formats.

Settings file

~/.proselignrc is an INI file holding defaults for rewrites. Command-line options win over environment variables, which win over the file. It is refused if other users can write to it. The sample in examples/proselignrc (installed under /usr/share/doc/proselign/examples/) documents every key.

[rewrite]
voice = Bryan            # used when --voice is not given
strength = 0.5
[backend]
endpoint = http://127.0.0.1:11434/v1
model = qwen2.5:14b-instruct
offline = on
[style]
passive_voice = off      # write actively; passages are redone until they are
en_dashes = off          # ranges become 2019-2021
em_dashes = off          # the model rephrases; commas as a last resort
exclamation_marks = on
semicolons = on
ai_artifact_filter = on  # preambles, sign-offs, stock phrasing, curly quotes
first_person = plural    # "we/us/our", never "I/me/my" (voice, plural or singular)
avoid_words = appears, consistent with, rather than   # never written; sentences with them are reworded

Rules the model can break are checked after every attempt and fed back for another try; punctuation still left at the end is replaced mechanically. Quotations, inline code, URLs and e-mail addresses are never altered.

Security & privacy

  • No telemetry, no network by default. The only connections Proselign makes are to the endpoint you configure and, when you give train a URL, to that site; --offline restricts both to loopback.
  • Documents are data, never instructions. Ingested text and text being rewritten are delimited with per-request random markers, so embedded "instructions" cannot escape into the prompt.
  • Private storage. The voice store is created 0700 and manifests 0600 regardless of your umask; writes never follow symbolic links.
  • Symlinks are not followed when walking a corpus directory.
  • Exports disclose little. Corpus paths and hashes are stripped unless you ask for them.
  • Tested against MITRE's "Lucky 13" unforgivable vulnerability classes on every change, alongside Bandit, Semgrep, CodeQL, dependency audits and secret scanning.
  • Attribution. Rewriting text in someone else's voice without their consent is impersonation. Use voices you own or are authorized to use, and disclose assisted writing where it matters.

Report vulnerabilities privately as described in SECURITY.md.
